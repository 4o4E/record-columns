# 多列聊天记录

`record-columns` 是适用于 LiteLoaderQQNT 的独立插件，用来逐列浏览 QQ 合并转发中的嵌套聊天记录。插件面向 Windows；当前仅确认适配 QQ 9.9.36-53644，其他 QQ 版本或加载器版本未经确认。

多列浏览、回复原文对话框和原图查看已完成实际验证；内层聊天记录的独立转发尚未完成，插件尚未通过完整验收。

## 构建与安装

需要 Node.js、pnpm，以及已安装 LiteLoaderQQNT 的 QQ 环境。

1. 将本项目放在本机目录，在项目目录执行：

   ```sh
   pnpm install
   pnpm run build
   ```

   构建会生成 `dist/renderer.js`、`dist/main.cjs` 和 `dist/preload.cjs`；插件清单 `manifest.json` 通过这些文件声明入口。
2. 将整个 `record-columns` 插件目录（至少包括 `manifest.json` 和构建生成的 `dist/`）放到 LiteLoaderQQNT 的插件目录中。若目录中尚无 `dist/`，先完成上一步构建。
3. 在 LiteLoaderQQNT 的插件管理中启用“多列聊天记录”，然后按加载器要求重启 QQ，使主进程、预加载脚本和渲染器入口一起加载。

更新时替换插件文件并重新构建，再按同样方式重新加载。不要只复制源码文件而省略清单或 `dist/` 构建产物。

## 使用

在 QQ 设置的 LiteLoader 插件列表中选择“多列聊天记录”，通过“启用多列聊天记录”开关控制功能，默认开启。设置会保存，已有记录窗口立即同步，无需重启 QQ。

关闭后，所有已打开的记录窗口恢复 QQ 原生界面；再次开启时从各窗口的根记录开始浏览。关闭状态下新打开的记录同样使用原生界面。

1. 在 QQ 中打开一条合并转发的聊天记录，进入其记录查看窗口。根记录以单列展示。
2. 点击某条嵌套聊天记录卡片，在右侧打开该记录的新列；当前父卡片会高亮。继续点击子记录即可逐层展开。首次展开时会扩大窗口，并保持窗口控件位于屏幕可见区域内。
3. 每列可独立滚动。选择其他分支时，当前分支后方的列会被替换；关闭后续列可回到较浅层记录。阅读位置按列保留，不需要在列间同步滚动。
4. 在记录卡片上右键可打开转发菜单和 QQ 接收对象选择界面。取消选择不会改变当前阅读位置；没有单独的卡片转发按钮。
5. 点击消息中的回复区域，在独立对话框中查看被回复的原消息；不会在消息行内展开。双击其中的图片可打开 QQ 原生图片查看器。

窄屏会自动将左侧祖先列折叠为窄条，为最右侧记录保留阅读宽度。点击箭头可手动折叠或展开，展开后保留该列的阅读位置；手动展开后空间不足时，可水平滚动查看各列。

父级选中消息的高亮表示当前展开路径。列顶部只保留必要的折叠、展开和关闭控件；单列展示时使用完整阅读区域。

消息内容加载或高度变化时，后续消息会随内容顺序排列，无需通过滚动刷新布局。屏幕外消息继续使用虚拟占位，长记录不会一次挂载全部消息。

插件按引用身份查找嵌入记录中的原文；原文缺失或已过期时会显示读取错误，不会用摘要或其他消息冒充原文。是否能够读取取决于 QQ 提供的记录数据。

## 兼容性与数据

插件通过 QQ 的私有模块、消息记录服务、原生消息组件、转发菜单处理器和媒体查看能力接入。私有模块编号、内部数据结构及渲染行为可能随 QQ 更新变化；当前仅已知兼容 QQ 9.9.36-53644，升级 QQ 后可能无法加载或无法正常读取、显示、转发记录。未验证其他版本，不承诺兼容。

插件不持久化聊天数据。构建依赖 `@vue/runtime-core`（VNode 创建）及 `@tanstack/virtual-core`；运行时不依赖 lite-tools 或调试插件，消息组件由 QQ 自身渲染器管理。
